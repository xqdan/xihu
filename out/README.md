# Generated artifacts

Everything in this directory is written by a script in `integration/pipelines/` (or a search in `integration/detailed/`), except the artifacts listed under "Written by the design workflows" below. Do not edit these files by hand; rerun the generator and commit the result together with the change that caused it. Tests bind many of these files to their sources by sha256, so a stale artifact fails `npm test`.

| Directory | Content | Generator |

## Written by the design workflows

The detail-stage design workflows in `integration/orchestration/` (D group: `design.detail.freeze`, `.workload`, `.events`, `.execute`, `.integrate`, and `design.converge`) also write here. Workflows have no filesystem access: each returns its artifacts and the main loop persists them, so there is no generator script to rerun — regenerate by rerunning the workflow. They land in the same directory as the Stage B artifacts they consume, a `<stage>.json` artifact plus a `<stage>_run_record.json` recording the stage, source commit, inputs, strategy versions and the freeze fingerprint. Every number in them is either transcribed from a `stage_b.js` artifact or computed by the workflow itself; no agent contributes one.

| Directory | Content | Generated by |
|---|---|---|
| `detailed/` | B0–B5 detail artifacts (`detail_freeze.json`, `detail_workload.json`, `detail_events.json`, `detail_execute.json`, `detail_integrate.json`), their `*_run_record.json`, and the convergence proposal (`converge_proposal.json`, `converge_run_record.json`) | the D-group design workflows |

`converge_proposal.json` is a **proposal**, not a gate conclusion: it carries `isGateConclusion: false`. Gate verdicts live in `governance/` and are computed only by `integration/governance/evaluate_gates.js`.

One file is only partly generated: `direction/directional_workload_baseline.json` is the Stage A workload baseline of 2026-09-21; `sync_baseline_spec.js` rewrites only its K3 calibration block, the other fields are maintained by hand (explain the change in the PR).

The Stage A/B artifacts embed the git HEAD and the generation time, so regenerating them always produces a diff; compare the numeric fields, not the whole file.
