# Generated artifacts

Everything in this directory is written by a script in `integration/pipelines/` (or a search in `integration/detailed/`), except the artifacts listed under "Written by the design workflows" below. Do not edit these files by hand; rerun the generator and commit the result together with the change that caused it. Tests bind many of these files to their sources by sha256, so a stale artifact fails `npm test`.

## Written by the design workflows

The design workflows in `integration/orchestration/` also write here. Workflows have no filesystem access: each returns its artifacts and the main loop persists them, so there is no generator script to rerun — regenerate by rerunning the workflow. Each cycle lands a `<stage>_winner.json` / `<stage>_report.json` / `<stage>_proposal.json` artifact plus a `<stage>_run_record.json` recording the stage, source commit, inputs, strategy versions and (for the detail chain) the freeze fingerprint. Every number in them is either taken from a script artifact or computed by the workflow itself; no agent contributes one. For the four C-group domains that is checked, not asserted: the candidate numbers reach the workflow through `integration/pipelines/search_brief.js`, and `npm run workflow:verify-landed -- <domain>` confirms after landing that the winner is a verbatim row of the candidate artifact.

Two of these land outside `out/` on purpose. `design.learn` writes `references/sota/` — domain knowledge, which is not evidence and carries no repo provenance. `design.audit`'s optional external reference frame writes `references/external/`; it is ungated by the audit verdict because the four lenses failing does not make the reference frame false, and because intake gates admit only `out/` artifacts, so nothing under `references/` can be cited as evidence. A hand-authored brief is not a generated artifact and does not belong here: `design.intake` lands `teams/council/inputs/design_brief.intake.json`. The per-stage briefs of the budget contract's consumers are not stored at all — they are derived per run from the contract (`integration/pipelines/make_brief.js`), because a stored copy of a contract number is the copy that goes stale.

`governance/design_ledger.json` is the one file here that no workflow lands. It is the main loop's own record: every workflow returns a `ledgerPatch`, and `run_workflow.js` merges it in after the workflow's files have landed (`--land` only). It therefore goes through neither of `land.js`'s gates — `out/governance/` is a landing prefix for `design.dgate` and `design.backflow`, and the ledger is not either one's output. `npm run workflow:ledger-check` validates what is on disk.

`converge_proposal.json` is a **proposal**, not a gate conclusion: it carries `isGateConclusion: false`. Gate verdicts live in `governance/` and are computed only by `integration/governance/evaluate_gates.js`.

One file is only partly generated: `direction/directional_workload_baseline.json` is the Stage A workload baseline of 2026-09-21; `sync_baseline_spec.js` rewrites only its K3 calibration block, the other fields are maintained by hand (explain the change in the PR).

The Stage A/B artifacts embed the git HEAD (and no wall-clock time), so regenerating them on a new commit changes only the provenance fields and the sha256 chain that depends on them; `tests/governance/test_regeneration_reproducible.js` pins the commit and requires a byte-for-byte match.
