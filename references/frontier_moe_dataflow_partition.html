重叠：读取如何被计算和归约盖住

暴露 MC 不是「还要再读多少字节」，而是：计算和归约已经把时间占满之后，读取还有没有多出来。 重叠发生在一张卡、一个 Stage 里，两条时间线并行。引擎（有预取缓冲时）取大： T_stage = max(T_net, T_compute + T_AR + T_补读)。

消耗 vs 暴露

计入版：SRAM、重叠、互联、多用户、Prefill

用引擎的分片部署（当前卡数、全分片、专家切 TP 份）。 消耗 MC = SRAM 扣掉常驻之后每步仍要从 MC 搬的字节 × 步频（目标 TPS/usr）；确定性权重读 1 份，MoE 独特专家随 batch 变多，KV/算力/集合通信 payload × 并发用户。 暴露 MC = 重叠后仍露在关键路径上的读取（已被计算+归约盖住的不算缺带宽）。 互联按 all-reduce 体积 2·(TP−1)·payload 计。Prefill 按「权重读一次 + 写满 KV + 前缀注意力积分」。

表头各列是什么

步频 = 页首目标 TPS/usr。前两列是 MC/HBM，中间是 SRAM 少搬了多少，后两列是 片间互联（不是内存带宽）。卡数下限取这几项里最大的。

SRAM 后消耗
SRAM 常驻扣掉之后，每步仍要从 MC 搬走的字节 × 步频。下面「净 xx/步」是一步的字节，「x 卡」按每卡有效 MC 折算。问的是：MC 总线有多忙。 读取就算被计算盖住，这列也不会变小——字节还是搬了。
重叠后暴露
步时取 max(T_net, 计算+归约+补读)。忙碌更长 → 已掩盖：再加 MC 换不来 TPS。读取更长 → 红尾换成 TB/s，才是露在关键路径上的带宽。问的是：步时还缺不缺 MC。 消耗是「搬了多少」，暴露是「有多少还在拖步时」。
SRAM 省/步
因为片上 SRAM 已常驻一部分权重，每步少从 MC 读的字节（全系统）。SRAM 先留作预取缓冲，剩下优先扣确定性权重，再按命中率扣 routed。所以消耗一定低于朴素 MC。重叠不进这一列——重叠不省字节，只省关键路径上的时间。
互联 2(TP−1)·payload
片间链路，不是 MC。环 all-reduce：reduce-scatter 走 (TP−1)·payload，all-gather 再走一遍，导线总字节 = 2(TP−1)·payload。payload 是这一步要归约的向量（随 batch 放大）。TB/s = 每步导线字节 × 步频；「x 卡」按每卡链路带宽折。
归约 ms/步
集合通信在时间上要占多久：次数 × 启动延迟 + payload 传输（延迟几乎不随 batch 涨，体积会涨）。表里写成 μs。1000 TPS 的预算是 1000 μs。超了不能靠加 TP 摊薄层数带来的次数。上一列是链路上有多少字节，这一列是 1 ms 窗口通不通过。
对照
配多少 HBM/MC → 先看消耗，已掩盖则加 MC 无 TPS 收益。步时缺不缺带宽 → 暴露。SRAM 值不值 → 省/步。配多少片间链路 → 互联 TB/s。目标步频通不通过 → 归约时间。

步频 = 目标 TPS/usr。系统 token/s = 步频 × 用户数。卡数下限取 Decode 消耗 MC / 暴露 MC / 互联 / 容量 / 归约时间 的最大者。

Batch 变大：权重摊销 vs 独特专家涨流量

同一 replica、Decode、步频仍按「每用户 TPS」。batch = 并发序列数。 稠密层权重确实只读 1 份，算术强度随 batch 上升；MoE 不是：每个新 token 可能点到还没读过的专家， 独特专家数 ≈ E · (1 − ((E−k)/E)B)，专家权重流量先涨、饱和后才像稠密。 算力与 KV、归约 payload 仍 ×B；归约延迟几乎不涨。

每用户 TPS（随 batch 下降）

系统 token/s = TPS/usr × batch（先升后饱和）

独特专家数（饱和于 E）

掩盖倍数 = 忙碌 / T_net（>1 则读取被盖住）

高亮行 = 页首「并发用户」。步时 = max(T_net, 忙碌)×1.17。容量超了仍给出时间线上的可达 TPS，表示「若装得下会跑多快」。

怎么保证 batch 变大时每用户 TPS 不掉很多

同一 replica 上，一步 Decode 给 batch 里每个人各吐 1 个 token。每用户 TPS = 1 / 步时，步时 = max(T_net(B), T_busy(B))。 B 涨则独特专家、KV、算力、归约 payload 都涨，步时变长，TPS/usr 必然掉——除非把「多出来的 B」从这条关键路径上拿掉，或让增量小到仍被盖住。

1. 副本扩出去，replica 上保持小 batch（主手段）
要 1000 TPS/usr，优先 N 份 replica × B=1～2，不要 1 份 replica × B=8。总并发 = N×B，每人看到的仍是 T_step(小 B)。Decode 与 Prefill 拆开，Decode 舱专跑小 batch。系统吞吐用加副本换，不拿单用户时延去换。
2. 压住 T_net 随 B 涨：独特专家 + KV
K3/V4 的增量主要是新专家权重；GLM-5.2 在 1M 上 KV 比权重大，B=2 就接近腰斩。杠杆：路由粘性/热点专家（独特集合远小于均匀假设）；SRAM/热专家缓存按 unique(E,k,B) 而不是按 top-k 来配；真 EP 让每卡只读自己的专家分片（本页默认是专家切列，每卡仍看到全部独特专家）；V4 这类压缩 KV 才能在长上下文上 batch。
3. 压住 T_busy 随 B 涨：算力与归约
V4-Pro 在 TP32、B=1 已是归约墙，再加 B，payload×B 直接拉长步时。杠杆：降 TP、加副本（通信次数按层走，不按用户摊）；集合通信融合；降启动延迟；链路带宽只缩短 payload 段。算力墙则要更多 L-Core 或把 batch 拆到更多 replica，单卡算力不够时加大 B 只会更慢。
4. 让增量仍落在重叠窗里
若 B=1 时 T_net 已被忙碌盖住，且新增 KV/专家读仍短于忙碌增量，TPS/usr 掉得慢。这要求：B=1 就要有余量（掩盖倍数明显 >1），并且增量主要是可重叠的 MC，而不是归约延迟。K3/GLM 在 TP32 上 B=1 仍露尾，加大 B 会先把露尾加长，没有「免费窗」。

TP32、1M、预测 80% 量级：B=2 时 K3 ≈73%、V4 ≈76%、GLM ≈53%（GLM 被 1M KV 打穿）。要「掉得不多」（例如仍 ≥80%），这套卡上 Decode batch 宜停在 1，最多 2；更多用户用加 replica。芯片侧则是更大 SRAM（装独特专家）或更小 KV（压缩注意力）或真 EP。

重叠 + SRAM 常驻之后，TP 不受限能否保证盖住搬移？

能盖住，但盖在归约上，不是盖在算力上。重叠取 max(T_net, T_compute + T_AR + T_补读)。 全分片时 T_net 和 T_compute 都随 1/TP 掉；SRAM 常驻让每卡工作集一旦小于 768 MiB，T_net 掉得更快。 T_AR 几乎不掉：次数按层走，启动延迟与 payload（模型里按完整 hidden，不随 TP 摊）是地板。 所以存在某个 TP*，之后 T_AR > T_net，读取被掩盖。

不能保证：用算力把 MC 盖住
Decode MoE 算术强度远低于脊点。TP 把 FLOP 和字节按同样比例切开，T_compute / T_net 几乎不变。没有归约、只靠重叠+SRAM 时，在小 TP 上永远是带宽墙。SRAM 只在「每卡切片已经装得进片上」的极大 TP 才可能让 T_net 掉过 T_compute。
能保证（渐近）：用归约地板把 MC 盖住
1M、B=1、预测 80%、flat 归约：V4-Pro 在 TP32 已掩盖；K3、GLM-5.2 约 TP64 起掩盖。再加大 TP，掩盖倍数继续升，但 TPS/usr 锁在 1/T_AR 附近：K3 ≈940–1000，V4 ≈1420–1550，GLM ≈1230–1270。再加卡换不来单用户时延——已经是通信墙。
这不是免费午餐
头数上限：K3 96、V4 128、GLM 64。GLM 刚好卡在 64 头才盖住。专家切成 TP 份后列宽 expertHidden/TP 变窄，L-Core 利用率掉，算力更短、更依赖归约去盖。Batch>1 时独特专家和 KV 抬高 T_net，掩盖所需的 TP* 会更大。复制张量省归约会让 T_net 不再按 1/TP 掉，掩盖更没了。
若目标是 1000 TPS/usr
掩盖 ≠ 达标。K3 盖住时已经贴着归约天花板；要再快只能降每层 AR 次数/延迟，不能靠无限 TP。V4 在 TP32 就既掩盖又超过 1000。无限加卡是在用通信时间当遮羞布，把带宽问题变成延迟问题。
