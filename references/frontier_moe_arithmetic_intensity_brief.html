I 怎么从 Decode 变到 Prefill

先分清「强度」是什么、矩阵挂哪颗核、带宽怎么切，再谈线性 / 注意力 / batch / TP / CP 怎么改 I。

I_MC
算术强度，只看 Memory Channel（HBM）搬了多少字节，不含片间网。单位 FLOP/Byte。I 高偏算力墙，I 低偏带宽墙。 算子 I_MC 是单个 GEMM 或注意力核：线性 Decode 约为 2×参数 / 权重字节（MXFP4 Routed ≈ 3.76，BF16 = 1）。 定 H 用的是 Prefill 整模 I_MC：把这张卡上的线性+注意力 FLOP 加总，再按 TP×CP 切开，分母只留本卡要读的权重和 KV。
I_MC = FLOP / HBM
整模 Prefill　I_MC = [(线性 + 注意力) / (TP · CP)] / (权重/TP + KV/CP)
I+网
同一套 FLOP，分母再加导线：TP 环 all-reduce ≈ 2(TP−1)·payload·tokens（Decode tokens=B，Prefill =S/CP）， CP 搬 KV ≈ 2(CP−1)/CP · KV。比 I_MC 更稀，只判断会不会先碰到网墙，不拿来压低 H 算力档。TP=1 且 CP=1 时与 I_MC 相同。
I+网 = FLOP / (HBM + 2(TP−1)·payload·tokens + 2(CP−1)/CP·KV)
挂核
PD 同时在线：L 跑 Decode，H 跑 Prefill。Decode 矩阵尽量挂 L；若该算子 I 高于「PD 下 L 脊点」= 原 L 脊点 / Decode 份额，则临时上 H（抢占一段时间，H 矩阵峰值不把 Prefill 和 Decode 注意力加在一起）。 Prefill 矩阵始终挂 H。伴随 Vector 跟矩阵走：线性侧的 Norm/SiLU 跟线性，RoPE/Softmax 跟注意力。
PD 带宽
L 与 H 共用 3.58 TB/s，按 Decode / Prefill 份额调度，不是各吃满。默认 Decode 80% / Prefill 20%。 份额下有效脊点 = 原脊点 / 份额：Decode 分得多，L 脊点变高（注意力更不容易溢出）；Prefill 只剩 20%，H 脊点变稀。 Vector 匹配 TF = I × (份额 × 3.58) / 0.8。H 矩阵峰值仍按满带宽 I_MC 定，不被 20% 压低。
线性 GEMM
Decode 一步：权重读一份，FLOP 按 1 token 计，所以 I 就是 dtype 决定的那个常数。Prefill 每卡仍然只读一份权重，但本地要算 s=S/CP 个 token，FLOP ×s，于是 I × (S/CP)。CP=1 时就是 ×S。 TP 把权重和 FLOP 一起切开，线性算子 I 不变。
因果稠密注意力
MLA / HCA / indexer：Decode 每步只对当前 Q 扫已有 KV，FLOP 与 KV 字节都随 L 同比涨，I 与 Context 无关，矩阵核默认挂 L。 对全量因果注意力，Prefill 因果积分 FLOP ~ S²、写出 KV ~ S，算子 I 近似为 (S/2)×Decode；CSA/HCA/DSA/top-k/窗口等固定工作集必须按各自实际工作集单独计算，不能套用该比例。矩阵核挂 H。Softmax/LSE 走 Vector。 定 H 不要直接用这段算子 I×S，否则会到十万量级；改用整模 I_MC。
MLA / MQA 怎么切
潜变量 KV 跨头共享（V4 还是 MQA），不能按头切 KV。TP 只切 Q 头：FLOP ÷TP，每卡仍读完整 KV，所以算子 I ÷TP。 要摊 KV 容量和本步 KV 带宽只能走 CP（切序列）：Prefill 上 FLOP 与本地 KV 同 ÷CP，MC I 不变。 引擎里「MLA CP=TP」指用 TP 组做 Context 分片，不是切头。
固定工作集
DSA/CSA topk、滑动窗：每查询搬的状态差不多，Prefill I ≈ Decode I。Decode 仍挂 L、Prefill 仍挂 H。 KDA / RMSNorm / SiLU / RoPE / Softmax / 残差是 Vector，I 几乎不随 S、B 变，不单独改挂 L/H。
Decode batch
B = 同一 replica 并发序列。稠密权重读 1 份、FLOP ×B，所以 I ×B。Routed 独特专家 ≈ E·(1−((E−k)/E)B)，字节随独特集合涨，I ≈ I₁·B·k/uniq，碰撞少时几乎不涨。 注意力与 KDA：FLOP 和状态都 ×B，I 不变。预取 (2−p) 只放大 Decode Routed 分母；Prefill 按 p=1 读一份专家。
TP / CP
TP 切稠密权重：在只看 MC、且 FLOP 与权重同步分片的理想模型中，GEMM 的 FLOP 和权重同 ÷TP，线性 I 不变；计入 All-Reduce/All-Gather 后的 I+网 会下降。MLA/MQA 只切头，注意力 I ÷TP。Decode 看 TP=1/8/16，Prefill 另加 32。 CP 切序列 / KV。每卡 s=S/CP：线性 I ×s；MLA 注意力 MC I 不随 CP。Decode 一步 Q 不切，CP 只摊本步 KV。

各算子怎么切，I 怎么变

三条轴：TP 切张量（头或列），CP 切序列 / KV，EP 放专家。 强度只在「FLOP 和字节不同步 ÷」时才变。全分片下线性 GEMM 两边一起除，所以看起来像「切了也没变」。 下面是算子 MC I；计入导线后的整模 I+网更稀，见 Prefill / Decode 段落。

线性 GEMM：FLOP 与权重同 ÷TP，I(TP)=I₁ 不变。Prefill 每卡读一份权重、本地 s=S/CP，I(CP)=I₁·S/CP。Decode 稠密 I(B)=I₁·B；Routed 按独特专家，B 增大时 I 几乎不涨。

MLA / MQA 核：KV 不按头切。TP 切 Q 头，I(TP)=I₁/TP。CP 切序列，FLOP 与本地 KV 同 ÷CP，MC I(CP)=I₁。对全量因果核 Prefill 再乘长度：I≈I₁·S/(2·TP)；top-k/窗口/DSA/CSA 等固定工作集不乘 S，按实际流量计算。

Vector：I(TP,CP,B,S)≈I₁。KDA 状态不随 L，CP 摊不掉。

Decode Roofline

一步 Decode，并发序列 B=1 / 16 / 32，切分 TP=1 / 8 / 16。 矩阵核默认挂 L。PD 并行时 Decode 只分到 80% 带宽，L 脊点变成「原脊点 / 0.8」，比满带宽更苛刻：注意力 I 更容易高于这条线，于是临时上 H。 H 同时在跑 Prefill，所以溢出是抢占/分时，H 矩阵规格不把 Prefill TF 和 Decode 注意力 TF 加在一起。MLA/MQA 核 I÷TP：加大 TP 常能让注意力回到 L。

L-Core：线性默认留在这

B=1 时专家 GEMM 的 I 就是 MXFP4 的 ≈3.76，远在 L 脊点左侧，永远是带宽墙。BF16 稠密层 I=1，更靠左。

B 加大后，稠密权重仍读一份、FLOP ×B，I ×B：B=16 时 I=16，B=32 时 I=32。Routed 独特专家随 B 涨，字节分母也涨，I 从 3.76 只升一点，仍进不了算力墙。

因此定 L 不用 Routed，而用 B=32 稠密 I=32：匹配 143 TF，上取到 196.6 TF。只跑 B=1 可以更小；兼顾 B=16 用中间档。

H-Core：只接溢出的注意力

注意力 I 不随 B（FLOP 和 KV 都 ×B）。三模型 Decode 的代表性高强度核包括 V4 CSA topk / HCA、K3 MLA 吸收后、GLM DSA topk。具体 I 取决于当前 Context、压缩/索引工作集和实现口径；固定 top-k/窗口核通常近似不变，全量 KV 核则需按实际流量重算。

PD 下 L 脊点大约 50+。TP=1 时 181 和 256 都溢出到 H；TP=16 后 I÷16，多数能回到 L。溢出时 Softmax/RoPE 跟着上 H-Vector。

加大同一 replica 上的 Decode batch，换不来「专家也进算力墙」。要抬系统吞吐，优先加副本、保持小 B。

TP 越大，I+网分母里通信越多，有效 I 越稀，更不可能靠加卡把 Decode 整模推进算力墙。I+网只说明网会不会先堵住。

Prefill Roofline

一条 Prefill 序列，切分 TP=1 / 8 / 16 / 32 与 CP=1 / 8 / 16 / 32。 线性 + 注意力矩阵都挂 H-Core，L 图空——L 留给同时在线的 Decode。 工作切分取 TP32×CP32：每卡本地 s = 32K/32 = 1024 token。

算子 I：线性必然算力墙

权重复用把线性 I 抬到 I₁×s。CP=1 时 ×32768；CP=32 后仍是 I₁×1024，通常远高于 H 脊点。所以 Prefill 线性打到 H 上就是算力墙，不要再用 Decode 的 L 去喂这段。

MLA/MQA 不能按头切 KV：TP 只切 Q 头，I÷TP；CP 切序列则 MC I 不变。对全量因果注意力，算子 I 近似 ×S/2；DSA/CSA top-k 与窗口则按实际工作集计算，同样挂 H、I÷TP。

整模 I_MC：用来定 H

把线性 FLOP 和注意力 FLOP 加在同一张卡上，分母是本卡权重 + 本卡 KV。TP 摊权重，CP 摊 KV 和 token 数。

I_MC = [(线性 + 注意力) / (TP · CP)] / (权重/TP + KV/CP)

32×32 时整模 I_MC 应由完整分析页按当前 Prefill 长度、注意力工作集和通信模型动态计算。I+网把环和 KV 导线加进分母，更稀，只对照网墙；CP 越大，通信占比通常越高，是否先碰到网墙需按实际 payload 与 KV 流量判断。

Vector 算子

逐元素与非线性不进 L/H 矩阵 Roofline。RMSNorm、残差 Add、SiLU 跟线性走；RoPE、Softmax/LSE 跟注意力走；KDA 状态更新留在 Decode 的 L（I≈1.75，低于溢出线，不上 H）。 I 几乎不随 B、S、TP。相对 MC 多在带宽墙；融合进矩阵核时不另占 MC。墙必须用该核分到的带宽来量，见下一节。

PD 并行 · L / H 各自的 Vector

L 跑 Decode、H 跑 Prefill，MC 按 Decode 80% / Prefill 20% 切开。 满带宽时 Vector 按 KDA I=1.75 只需约 8 TF；切开后每路带宽变少，匹配 TF 按份额缩小。 但 H 要同时伺候 Prefill Vector 和溢出过来的 Decode Softmax/RoPE，ALU 按两路 TF 相加。加大 TP 后注意力 I÷TP，多数模型回到 L，H-V 不再叠加 Decode 路。

Vector 匹配 TF = I × (份额 × 3.58 TB/s) / 0.8

L-V：Decode 留在 L 的 Vector（线性侧；未溢出时含 Softmax/RoPE）。KDA I=1.75 × Decode 80% 带宽，匹配约 6 TF，上取 8.2 TF。

H-V：Prefill Vector × Prefill 20%，加上溢出伴随 Softmax/RoPE × Decode 80%。矩阵峰值不叠加；Vector 要叠加。档仍 8.2 TF。

按算术强度重定 L / H 算力

带宽不动，利用率 0.8，F_match = I × 3.58 / 0.8，再上取到 Tensor 档。 旧 CHIP_DEFAULT 是 L 262 / H 2097、利用率 0.6，Vector 按 H/32+L/64 捆在矩阵上。本页把 L / H / L-V / H-V 拆开。 I+网、8×8、16×16、Decode 注意力最坏 TP 只作对照，不定档。

F_match = I × 3.58 TB/s / 0.8

L 矩阵 196.6 TF：Decode 线性默认挂 L。B=32 稠密 BF16 I=32 匹配 143 TF，上取 196.6。注意力 I 高于 PD 下 L 脊点时临时上 H，不抬 L。

H 矩阵：按「能大尽量大」，

H = max(Decode 注意力最坏 TP 满带宽, Prefill TP32×CP32 整模 I_MC 满带宽)

Decode 注意力需求按 Decode 自身 TP 候选计算；Prefill 整模 I_MC 由完整分析页动态计算。PD 的 20% 只改 H 脊点和 H-V，不直接压低 H 矩阵峰值。

L-V / H-V 各 8.2 TF：按份额匹配；溢出时 H-V 两路叠加，仍落在同一档。

Decode 注意力是否随 Context 变化取决于工作集模型：固定 top-k/窗口近似不变，全量 KV 需随实际流量重算。H 应由 Decode 最坏 TP 与 Prefill 32×32 整模 I_MC 的动态最大值决定。

收口　Decode 默认挂 L、Prefill 全部矩阵挂 H；溢出抢占 H，矩阵峰值不叠加。L 按 Decode B=32 稠密贴脊点；H 按 Prefill 32×32 整模 I_MC 动态选择并尽量上取；3.58 TB/s 按 D80/P20 切开，只改脊点和 Vector，不直接改 H 的原始峰值需求。

原文明确不用的三件事

1. 用算子 I×S 定 H——因果核会到十万，规格失去意义。
2. 用 I+网压算力档——那是网墙诊断，导线只会让有效 I 更稀。
3. 把 TP32×CP32 当成 I÷1024——线性 I 只随 CP 除以 32，TP 切权重时分子分母一起走。
