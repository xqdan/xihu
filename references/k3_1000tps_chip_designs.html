Kimi K3 · 目标 1000 TPS/usr：芯片规格空间中的代表性设计

给定目标单用户 TPS，把芯片规格（MC 数量/带宽/容量、SRAM、算力、归约延迟、互联）和卡数都放开， 部署方案（PP×TP、层内策略、专家切分）对每个芯片点单独优化。算法在物理约束下枚举规格网格， 找到每个芯片"达标的最少卡数"，再用帕累托前沿和设计原型挑出几组有代表性的规格。

系统架构与设计变量

单卡 = 1 个封装：8 颗计算 Die（L-Core 线性阵列 + H-Core 注意力 + 本地 SRAM 切片）经 UCIe 直连 N 颗 3D-DRAM MC。 模型先按 TP 切到卡（每 MoE 层 4 次卡间集合通信，MLA 注意力层另加一次 LSE 合并；把 Router 的 all-gather 单独算一次则为 5），再按 PP 切成串行 Stage；每卡内部再按 8 Die 分片。 图中彩色标签即本页搜索的芯片规格维度，灰色标签为部署决策。

算法

规格网格 + 物理约束7 个规格维度取离散档位做笛卡尔积。每个点先过三道硬约束：Die 面积预算（SRAM 面积 + 张量阵列 + MC PHY + 固定开销 ≤ 8 × 400 mm²，所以 SRAM 上限随 MC 数量和算力变化）、MC 带宽 ≤ 基线 × 上限倍数、权重 + KV 状态 ≤ 每卡容量（由部署优化内部判定）。
逐芯片求达标最少卡数 N*对每个芯片点，卡数从小到大枚举；每个卡数下枚举所有 PP×TP（TP 整除头数且 ≤ 上限）× 专家切分份数 × Router 分片/复制，取 TPS 最大者。第一个 ≥ 目标 × (1 + 达标裕量) 的卡数即 N*（裕量用于吸收建模误差，避免 1001 TPS 也算达标）。归约延迟随 TP 的缩放方式（内存语义平坦 / 消息语义 log₂）、Wdown/Router all-gather 是否融合、MLA Context 分片的 LSE 合并是否计入，按页首选择。这一步只用分片主导的策略子集做快筛（全分片 × Router 分片/复制 × Wup 分片/复制；Wup 复制在"归约慢 + MC 余量大"的角落会胜出，其余复制策略在 K3 上从未胜出），代表点再做全策略复核。
成本模型芯片成本 = 硅面积（1 分/mm²）+ 存储（容量 × 单价 × 高速溢价）+ 互联 + 归约延迟改进代价；系统成本 = N* × 芯片成本。代价系数全部可编辑，默认延续 ../../src/core/design_engine.js 的面积比例口径。注意：此口径下每卡固定成本为 0，"少卡堆芯片"天然占优，页尾的成本系数敏感性表用于检验该结论是否稳健。
帕累托前沿在（芯片成本, N*）平面取非支配集：同样卡数下芯片更便宜、或同样芯片成本下卡更少的设计才留下。所有达标设计画成散点，前沿高亮。
原型选点从达标集合中按 8 个原型各选 1 个：最少卡数、最低系统成本、最省单卡、带宽保守、少 SRAM、归约延迟保守、帕累托膝点、最大裕量。同一设计命中多个原型时合并。这样保证代表点覆盖"堆卡 vs 堆芯片"两端和中间折中。
代表点复核与紧约束对每个代表点用全策略空间重新优化部署，输出 PP×TP、层内策略、瓶颈、时间分解、面积分解。再把每个规格降一档重跑：降了就达不了标 → 必需；要加卡才达标 → 有代价；不影响 → 有余量。

输入

SRAM 的两层价值都已建模：① 预取缓冲——确定性权重按流式消费不需整层驻留，缓冲要装下「预取深度 × 每层预测专家」（Router 前必须到齐）+「归约空窗期间 MC 读满的字节」（compute 停在 all-reduce 上时 MC 继续读下一批 = 每卡带宽 × 每层归约时间）；装下后 MC 才能在计算 / 归约期间持续读，预测未命中的 (1−p) 份专家在 Router 之后串行补读；缓冲不足按覆盖比例退化为"Router 后才读专家、归约期间 MC 空转"。② 缓冲之外的容量常驻权重，直接减少 MC 读取。每次归约的 payload 按实际维度计（attention / Wup 输出 = hidden，Wdown / 专家合并 = latent，Router = 专家 logits，MLA 合并 = heads × (kvLatent + 2)）。

规格网格（每维的候选档位，JSON）

collectiveLatencyUs 是 TP8 规模下的一次 all-reduce 延迟，缩放方式见上方选择。默认档位对应 ../communication/sram_allreduce_comm_cost.html 的物理估算：2 / 1.5 μs 消息语义，1.15 μs 内存语义两轮经交换，0.85 μs 两轮直连，0.66 μs 8 卡一步到位直连（< 0.85 在结果里标为激进）。linearTflops 按 Decode 1000 TPS 搜下限（含 65 / 98 TF），不按 Prefill 配；H-Core 仍按 L-Core 8 倍同比计入面积。独立 H-Core 下限见总览页算力搜索。

成本 / 面积模型（JSON）

面积：SRAM 1.26 MiB/mm²；张量阵列 1600 mm² 对应 262 TFLOPS；MC PHY 每颗 12 mm² + 0.025 mm² 每 GB/s。存储成本按容量计价，带宽超基线部分按比例加溢价。
