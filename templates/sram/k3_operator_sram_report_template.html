固定算力与带宽，逐层评估 SRAM 对 TPS 的影响

93 层、24 个 Softmax MLA 层、69 个线性 Attention 层、92 个 MoE 层；把计算、DMA、通信和 SRAM 生命周期放进同一个事件时间轴。不再用 SRAM 覆盖率插值或两个整层时间简单取 max。

结论固定硬件算子公式调度/容量SRAM 曲线逐层与算子敏感性边界与复算
这是更细的工程估算，不是 K3 实测或已验证芯片规格。结构来自本项目 ../../src/core/design_engine.js / kimiK3。真实 K3 的投影形状、线性 Attention kernel、层顺序和预测 trace 未确认；本报告显式补齐实现假设。精细事件时间轴不等于输入参数已经精确。TPS 是整组 TP=32 系统每用户的 decode TPS，不是单卡独立运行全模型的 TPS。

1. 主要结果与容量建议

“99% 点”定义为当前扫描中最佳已测 TPS 的 99%，不是无限容量理论极限。工程配置容量 = 该工作窗口 ×1.25 后按 32 MiB 取整；这只是本次固定硬件和调度下的候选。它不取代跨模型容量预算、ECC、bank 映射、物理端口与 PPA 验证。

Attention 分片口径：本次与旧容量表不同，明确改成 context 并行

Softmax MLA：每卡负责 C/32 个历史 token，但计算所有 96 个 query heads 的局部 Attention。投影后先 all-gather Q / 新 KV；局部采用 absorbed MLA（QK 维度 576、PV 输出 latent 维度 512），最后合并 LSE 并 reduce-scatter 输出，再做 O projection。卡内用 8-head tile 执行，不能把“96/32=3 heads”同时套到 context 分片上，否则会重复除以 TP。

线性 Attention：状态按 heads 切分，每卡 3 heads；128×128 状态矩阵，BF16 读/写，FP32 更新工作区。Softmax 的 96-head 局部统计与线性层的 3-head 状态不会同时运算。卡内具体 head/context tile 如何落到 8 Die 仍是后续物理映射问题。

4. 同一事件时间轴上的 DMA、容量与计算

t_compute(tile) = max(FLOPs / effective_compute, SRAM_read_bytes / SRAM_read_BW, SRAM_write_bytes / SRAM_write_BW, weight_params / unpack_rate) + micro_launch t_collective = max(τ + 2 × payload / link_BW, SRAM port service time) DMA_rate(t) = min(external_mem_BW, fabric_BW − active_collective_fabric_rate, relevant_SRAM_port_BW − active_compute_port_rate) S_reserved(t) = fixed_scratch_arena + Σ allocated read/write/prediction objects S_reserved(t) ≤ configured_working_window ≤ physical_SRAM Raw step time = serial compute service + serial collective service + exposed waits TPS/usr = 10⁶ / (Raw step time[μs] × 1.17) Aggregate tok/s = B × TPS/usr
  • 真实排队：聚合 DMA 是一个共享 read/write 通道；输入 DMA 完成才能启动消费者，输出源在写回完成前继续占 SRAM。计算与 collective 串行，DMA 与两者并行；不存在遗漏计算时间的“无缓冲 min 回退”。
  • 非抢占 DMA：已发出的 tile 事务完成后才切换。队列选择为待写回/当前需求优先，再按消费者顺序预取。未来最多 D 层；KV 只预取当前 Attention 层。内存空闲也不允许超出 SRAM 预算无限读入。
  • 预测：一个完整预测 tile 内含 p 比例正确权重与 (1−p) 错误权重；Router 之前同等占用空间。Router 后才确认，错误部分释放，缺失部分补读。正在 DMA 的预测必须等完成；p 是字节比例的流体近似，不是假装已知真实专家 trace。
  • 空间不足：不发起可选预取；需求读可以淘汰最远期、尚未使用的 READY 对象，重读字节计入。当前 KV tile 跨 QK/Softmax/PV/head 循环保留，不能在第一次 QK 后释放。
  • Scratch：给算子临时对象预留全阶段最大值，作为固定 arena；报告同时记录实际活动对象峰值与已分配/预留峰值。这是偏保守、保证需求不死锁的分区实现，不是假定所有 SRAM 任意零成本复用。
  • 大容量不强制用满：直接贪心用满时可能预取太早、浪费带宽。本报告额外测试工作窗口 W≤物理 SRAM，取已测最快的真实调度结果；剩余容量闲置。此曲线是有限候选策略搜索，不是人为修改原始 TPS，也不保证全局最优。

容量增加后，还剩多少可消除的等待？

在本映射中，QK 与 PV 会对每个 head tile 重读 KV；因此外存只读一次的 KV tile，仍可能消耗多次片内 SRAM 读带宽。更多容量不能自动减少这些读访问，也不能消除 LSE 合并与其他跨卡归约。若要突破该平台区，应重新评估 head tile、数据复用、SRAM 端口及通信映射，而不是只增加 MiB。

7. 关键输入不确定性：B=8、物理 SRAM≤288 MiB

每行只改变表中一项，并重新搜索已测工作窗口；其他硬件相同。不是置信区间，而是说明“逐算子模型仍需正确输入”。内存有效带宽情景还受固定 4.096 TB/s fabric 上限限制。

带宽提高后若出现轻微负收益，是固定贪心调度、不可抢占的投机 DMA 与有限工作窗口搜索共同造成的策略效应，不代表更高物理带宽天然降低性能；此处没有同时优化带宽限流和所有调度策略。

8. 与旧文档的关系、局限与复算

本次结果优先用于 K3 decode 架构候选比较。旧容量表的 256/288 MiB 是不同 Attention 分片和完整两层预测池的对象预算；本次 SRAM 分配由事件调度决定，不要求两层全部到齐。旧 TPS 页的算力、存储带宽、LSE 口径与通信次数也不同。因此本次不能被解释为“证实旧 TPS 值”或“推翻旧容量表的所有对象需求”。
  1. 没有复用整个模型的整层时间 max 公式；但本模型仍是卡级资源的离散事件模型，不是 RTL/cycle-accurate、8 Die NoC 路由或真实 kernel trace。
  2. SRAM 总容量包含需求权重、预测权重、KV/read/write buffers、scratch 与 metadata；不额外叠加一块 288 MiB 池。物理 ECC、spare、RF 与 decoder 外围不在可用容量内。
  3. 当前可达性按聚合卡级池处理。若实际 L/H 本地 SRAM 不能被对应 DMA/算子使用，必须以每 bank/Die 峰值重跑；更大总容量不能解决局部无法访问。
  4. 没有硬件校准的 cache hit、prefix reuse、workspace“自动加速”；没有跨 token 常驻权重或 KV prefix 命中。每次 decode step 从空的预取缓存开始，完整计入首层启动及最后排空。
  5. 层间串行、shared 串行、一个 compute/communication 关键流。真实共享分支或 L/H 并行可更快；kernel 固定开销、端口冲突、通信拓扑尾延迟也可能更慢。
  6. 线性 Attention 仅按项目 128×128 状态近似，没有凭空知道 K3 实际 gating/convolution scratch。投影 residual budget 及层顺序不确定性在上方敏感性中暴露。
  7. DMA 将数据按固定有效带宽搬移，没有 DRAM row/bank、事务启动或 UCIe 包级周期模拟。预测正确率是字节比例近似；应以真实 expert route trace 校准非均匀热点。
  8. FP32 LSE gather/reduce、shared 单独归约及 Q gather 与旧页面不同，本次通信成本更完整但仍依赖部署选择。没有采纳旧页面“专家/Shared 无条件融合”的假设。
  9. 所有候选 S 维持相同 SRAM 带宽；因此只能用本次结果选择需要进一步物理实现验证的候选，不能直接从 MiB 推导面积、功耗或制程承诺。
