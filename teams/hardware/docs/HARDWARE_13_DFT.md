# HARDWARE-13：可测性设计（DFT）

- 所有者：Hardware（DFT/测试）；共签：V&V（覆盖判据）、Package（测试通道）
- 状态：**`OPEN`**——全部为决策框架。本仓库当前没有任何 DFT 依据
- 权威来源：`HARDWARE_11_FLOORPLAN_AREA.md`、`HARDWARE_12_CLOCK_RESET_POWER.md`、
  `09_PACKAGE_POWER_RAS.md`（封装测试通道）

## 0. 为什么这一篇全是 OPEN

DFT 的每一项（scan chain 数量、MBIST 分组、JTAG 拓扑、测试模式功耗、测试时间）都取决于
**综合网表、SRAM 宏、IP 的 DFT 支持情况**——这三样在本仓库里都不存在。

在别处可以写"决策框架 + 待定项"，因为框架本身有依据（比如需求来自某条已冻结的目标）。
DFT 连框架都没有依据：它是纯实现阶段产物。**本文的价值是先把"必须决定什么"列全，
让 P7 阶段不会漏项**，而不是假装已有方案。

**这一篇没有被任何模型产物引用，也不应该被引用。** 它不进 `out/`，不进 Gate 判据。

## 2. 与已有约束的冲突（这一节有依据）

| 冲突 | 内容 | 缓解方向 |
| --- | --- | --- |
| DFT 功耗 vs 热上限 | `09_PACKAGE_POWER_RAS.md` §4.2 明确列出 **DFT 是尚未计入 55.12 W 余量的项目之一**。Scan shift 与 MBIST 同时动作的功耗经常显著高于功能模式 | 分组测试、降低 shift 频率、限制并行 MBIST 组数；**必须在功耗预算里占一行**，见 `HARDWARE_POWER_BUDGET.md` |
| 测试模式频率 vs 固定主频 | 主域固定 1.0 GHz（`HARDWARE_12_CLOCK_RESET_POWER.md` §1），但测试通常需要降频 | 测试模式允许独立时钟，**不属于"降频换算力"** |
| 复位域 vs 测试复位 | `HARDWARE_12_CLOCK_RESET_POWER.md` §3 的复位顺序是为功能模式定的 | 需定义测试复位入口，且不得绕过 R-4（epoch/mailbox 确定性清零） |
| 面积余量 | Die 余量 34.659 mm²（8.7%），DFT 逻辑要吃掉一部分 | 计入余量；若超，走变更评审 |

## 3. 判据（可测性验收）

以下判据在 P7 之前不适用，登记在此是为了让"什么时候算完成"有定义：

1. 每个 SRAM 实例都在 MBIST 覆盖内，无遗漏清单；
2. Scan 覆盖达到与目标测试时间相容的最大值（具体值待综合后定）；
3. 测试模式功耗 ≤ 热签核给定的测试上限；
4. 整包 JTAG 链路可枚举全部 8 Die + 16 MC；
5. 测试时间满足 ATE 经济性约束（具体值待定）。

## 4. 未闭合项

全部 10 项均为 `OPEN`，责任在 P7 阶段的 Hardware 后端与测试团队。
**本文件在本轮设计中不产生任何冻结结论**，只保证事项不遗漏。
